# 연속 회전 PPO 실험 결과

추가 연구 학습 2,000,000스텝을 5개 구간으로 완료했다. 모방학습 없이 기존 순수 PPO 모델에서 이어 학습했으며, 관찰 5139차원은 유지했다. 기본 게임 환경의 새 시드 20개에서 기존 모델보다 점수 획득이 좋아졌다. 기존 기본 모델 파일은 교체하지 않았다.

## 최종 독립 평가

후보를 고정한 다음 처음 평가한 seed 61001~62910의 20개 에피소드다. 양쪽 모두 같은 시드, 기본 적·지형·스폰, 30Hz 행동 결정, greedy 정책, 최대 게임 시간 400초를 사용했다. 죽으면 그 시점의 점수를 최종 점수로 집계했다. 일찍 사망한 에피소드의 120초 점수도 최종 점수를 유지한다.

| 지표 | 기존 PPO | 연속 회전 PPO |
|---|---:|---:|
| 120초 평균 점수 | 1,049.25 | 1,530.00 |
| 120초 점수 하위 25% 경계 | 778.75 | 912.50 |
| 최종 평균 점수 | 1,508.00 | 2,902.00 |
| 최종 점수 하위 25% 경계 | 1,166.25 | 1,695.00 |
| 평균 생존 시간 | 222.67초 | 262.84초 |
| 평균 적 처치 | 4.30 | 8.25 |
| 400초 생존 | 2/20 | 5/20 |

최종 평균 점수는 **92.4%**, 120초 평균 점수는 **45.8%** 높다. 같은 시드의 최종 점수에서 14승 6패다. 시드 쌍을 함께 재표집한 bootstrap 10,000회의 평균 점수 차이 95% 구간은 +594~+2,282점이다. 120초 점수 차이는 +150~+818점이다. 생존 시간 차이는 +40.17초지만 구간이 -32.18~+111.79초이므로 생존 개선의 불확실성은 남는다. 하위 25%는 분위수 경계이며 최저 25%의 평균이 아니다.

원자료는 `corrected_heldout_baseline.json`, `corrected_heldout_candidate.json`, 시드별 비교는 `corrected_heldout_comparison.csv`, 판정과 구간은 `corrected_heldout_comparison.json`에 있다. TensorBoard의 `tensorboard/corrected_final_comparison`에도 기록했다. `corrected_training_progress.png`는 오류 수정 전 개발 평가 이력으로, 수정 후 독립 평가와 구분해야 한다.

## 학습 과정과 최종 모델

| 구간 | 추가 스텝 | 목적·결정 |
|---|---:|---|
| 001_aim_adaptation | 300,000 | 쉬운 천체 환경에서 회전·발사 적응, 이동·CNN·성장 고정 |
| 002_full_adaptation | 200,000 | 전체 정책 동시 적응, 생존 저하로 계획보다 일찍 중단 |
| 003_body_stability | 500,000 | 001에서 분기, 조준을 고정하고 이동·특징 추출 적응 |
| 004_body_continuation | 500,000 | 003을 연장했으나 부모 성능을 넘지 못함 |
| 005_aim_precision | 500,000 | 003에서 다시 분기, 이동·CNN·성장을 고정하고 조준·발사 정밀화 |
| 합계 | **2,000,000** | 후보 선택은 개발 시드로 수행 |

최종 파일은 `selected_model.zip`이다. 005의 `evaluated_001200000.zip`을 선택했으며 새 행동 형식의 학습 계보는 120만 스텝이다. 분기에서 사용한 전체 연구 비용 200만 스텝과 다르다. 원본 부모 모델의 기존 학습 1,474,560스텝도 별개다. 검증용 PPO 업데이트는 수정 전·후 각각 64스텝으로 연구 학습과 분리한다.

최종 SHA256: `205b19d907f233f4a89f6770008ce1a30d32f23d2921be3f380286b0163a8bea`.

이동은 정지·8방향, 회전은 tanh Gaussian의 -1~1, 발사는 Bernoulli, 강화 6종·진화 5종은 범주 분포다. PPO는 이 분포들의 결합 log probability를 학습한다. 5칸 Box는 전달 형식이며 이산 선택을 Gaussian 반올림으로 만들지 않는다. 기존 CNN·개체 특징 추출기를 재사용하고, 회전 헤드를 새로 학습했다. 성장 행동도 정책 출력이다.

## 진화 오류와 결과의 한계

최초 학습 200만 스텝 동안 디코더가 진화 인덱스를 `numpy.int64`로 전달했다. 공용 게임 코어는 Python `int`만 받아 진화 요청을 무시했다. 화면에서 기체가 계속 rookie인 점을 보고 추적했으며, 새 디코더에서 `map(int, choices)`로 변환해 해결했다. 공용 게임 코드는 수정하지 않았다. 실제 환경에서 레벨 10 보상을 선택해 twin으로 바뀌는 통합 검증을 추가했다.

진화는 적 기체 성장에도 영향을 주므로 초기 평가는 수정된 행동의 성능 근거가 될 수 없다. 최초 평가·선택·모델은 `initial_decoder_results/`에 보존했다. 당시 보고한 109% 개선 수치는 최종 결과로 사용하지 않는다.

수정 후 같은 가중치를 개발 시드 8개에서 확인한 뒤 모델과 재생 방식을 고정하고, 기존 최종 평가와 겹치지 않는 새 시드 20개를 평가했다. 위 표는 **실제로 진화가 적용되는 수정 후 결과**다. 오류 수정 후 추가 연구 PPO 학습은 하지 않았다. 따라서 정상 진화를 포함한 200만 스텝을 처음부터 학습한 실험이라고 해석할 수 없다. 수정 후 통합 검증용 64스텝 모델은 최종 후보에 합치지 않았다.

400초를 넘는 장기 생존과 다른 기기·라이브러리 버전의 동일성은 검증하지 않았다. 모든 시드에서 개선되지는 않았고, 일부 에피소드는 일찍 사망했다. 연속 회전만의 인과 효과를 분리한 실험도 아니다. 추가 PPO·보상 조정·계층별 동결과 함께 개선된 결과다.

## 실행 범위와 자원 제한 위반

추가한 학습 코드는 이 폴더, 디코더는 `../actions/rotation_continuous_action_decoder.py`에 있다. 기존 공용 게임·관찰·보상·설정·이전 모델의 보호 대상 40개 파일 해시를 비교한다. 프로젝트 규칙에 따른 `graphify-out/` 갱신도 수행한다.

**최대 8프로세스 제한을 작업 전체에서 지키지 못했다.** 학습·보조 평가가 겹쳐 Python 10개가 관측됐다. 별도로 graphify 기본 설정이 24개의 process worker를 사용했으며, 당시 전체 최대치는 측정하지 못했다. `process_limit_incident.json`, `graphify_process_limit_incident.json`에 원인과 기록을 보존했다. 이후 Windows named mutex·프로세스 예약 검사, graphify `GRAPHIFY_MAX_WORKERS=1`, 도구 자식 프로세스를 포함한 모니터링을 적용했다. 최종 수정 후 쌍 평가의 관측 프로세스 수는 5개였다.

004의 학습은 완료됐지만 Windows 실행기가 ExitCode를 읽지 못해 종료 1을 반환했다. 원래 실패 기록을 보존하고, manifest·체크포인트로 완료를 검증한 뒤 실행기를 고쳤다. 실험별 소스 스냅샷과 최종 스냅샷, 버전 잠금 파일, 시드·모델·디코더 해시로 재현 근거를 남겼다. 중단된 게임 상태까지 체크포인트에 저장되지는 않는다.
