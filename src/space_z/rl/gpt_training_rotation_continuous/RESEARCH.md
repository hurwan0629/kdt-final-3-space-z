# 연속 회전 PPO 실험 기록

## 목적과 조건

이동 9종·발사 2종·강화 6종·진화 5종은 이산 선택을 유지하고 회전만 tanh Gaussian 연속값으로 학습한다. 외부 관찰은 원본 5139차원이다. 모방학습·시범·자동 성장 제어를 사용하지 않는다.

기존 기본 모델 018의 순수 PPO 가중치 중 특징 추출기·이동·성장·가치 함수·발사를 재사용한다. 새 회전 평균 출력은 0에서 시작한다. 따라서 기존 체크포인트를 그대로 이어 학습하는 작업이나 완전 신규 학습과는 다르다. 새 실험 스텝 수와 부모 학습량을 구분한다.

## 실행 전 결정

- 연구 학습 예산: 2,000,000 환경 전이. 연결 검증에 별도 64스텝을 사용했다.
- 첫 300,000스텝: 벽·적 없는 aim 조건에서 회전·발사·가치 함수를 적응시키고 기존 몸체 정책은 보존한다.
- 이후 700,000 / 500,000 / 500,000스텝: 실제 기본 게임에서 적응·정밀화·안정화를 검토한다. 변경할 경우 결과를 보기 전에 이유를 남긴다.
- 100,000스텝마다 기본 게임 4개 검증 seed, 최대 200초로 평가한다. 각 구간은 50,000스텝마다 복구 체크포인트를 보존한다.
- 최종 후보를 8개 추가 검증 seed로 고른 뒤 고정하고, 처음 사용하는 20개 seed의 최대 400초에서 기존 기본 모델과 비교한다.
- 실행 조건과 seed, 선발 기준은 `protocol.json`에 학습 전에 기록했다. 평가 보상보다 실제 점수·생존 시간을 판단 기준으로 사용한다.
- 학습 worker 4개, Windows launcher와 coordinator를 포함해 학습 자체는 Python 6개이다. 별도 평가 한 개를 병행해도 소유 프로세스 총합은 8개 이하다.

## 사전 검증

`checks/results.json`: 디코더 범위·정수 선택·연속 회전 샘플링·결합 log probability·tanh Jacobian·기존 조준 입력 일치·발사 확률 가중치 이전·성장 마스크·PPO 갱신·저장 복원·실제 회전을 확인했다. 2,000개 샘플의 회전값이 모두 달랐다.

## 구현 경계

공용 코드에는 새 `actions/rotation_continuous_action_decoder.py`만 추가했다. 나머지 구현과 결과는 이 폴더에 둔다. 기존 학습 래퍼의 reset/step과 보상을 재사용하고, 생성자에서 TankEnv에 새 디코더를 주입한다. 게임 코어를 별도로 진행하거나 전투 이벤트를 중복 소비하지 않는다.

기존 기본 모델은 보존한다. 원본 및 기존 학습 소스 해시는 `scope_before.json`으로 고정했다. 기존 PPO 자체는 변경하지 않았다.

## 001: 조준 적응, 첫 100,000스텝

검증 seed 4개의 기본 게임 평가에서 새 모델은 120초 평균 695점·p25 467.5점, 200초 평균 1,136.25점, 평균 생존 166.27초였다. 기존 기본 모델은 같은 조건에서 각각 803.75점·606.25점·1,057.5점·155.08초였다. 연속 회전의 학습은 작동하지만, 초반 점수와 하위 성적 개선은 아직 없다. 계획한 300,000스텝을 마친 뒤 검증 순위가 가장 높은 체크포인트를 기본 게임 적응의 부모로 사용한다.

시간을 줄이기 위해 기존 모델의 최종 비교용 20개 seed 결과도 병행 계산한다. 이 결과는 최종 후보를 고정하기 전까지 열람하거나 선발에 사용하지 않는다. 새로운 모델의 heldout 평가는 후보 고정 후 한 번만 진행한다.

200,000스텝에서 검증 4개 seed의 120초 평균은 1,188.75점, p25 780점, 200초 평균은 1,402.5점, 생존 평균은 162.40초로 개선되었다. 동일 seed의 기존 모델보다 네 지표 모두 높지만 표본이 작고 선발에 반복 사용한 검증 seed이다. 이 결과만으로 일반화나 안정적 우위를 주장하지 않는다.

300,000스텝의 조준 적응을 완료했다. 기본 게임 검증에서 120초 평균 1,243.75점·p25 1,141.25점, 200초 평균 1,696.25점·평균 생존 160.30초였다. 첫 구간의 최종 체크포인트가 사전 순위 기준상 가장 높아 다음 구간의 부모가 되었다. 추가 8개 검증 seed 평가도 예약했다. 다음 700,000스텝은 계획대로 기본 게임·전체 정책 학습·score_v7·learning_rate=0.0001로 진행한다.

추가 검증 8개 seed에서는 001 모델의 120초 평균 940점·p25 703.75점, 200초 평균 1,161.25점·생존 124.90초였다. 같은 seed의 기존 모델은 120초 평균 1,026.875점·200초 평균 1,285점이었다. 첫 4개 검증 seed에서의 큰 개선은 더 넓은 표본으로 재현되지 않았다. 001만으로 성공 판정하지 않고 계획한 기본 게임 적응을 계속한다. 이 8개 seed도 이제 관측한 개발 데이터이며 최종 독립 검증은 별도로 유지한다.

seed 505의 실제 게임 화면을 `visual_001_seed505/`에 저장해 확인했다. 100초 1,605점·6킬, 200초 2,375점·8킬·HP 200이었다. 캡처는 실제 정책의 결정과 게임 렌더러를 사용했다. 한 seed의 좋은 장면으로 일반화 성능을 주장하지 않는다.

## 002: 기본 게임 적응과 계획 수정

추가 100,000스텝, 새 행동 누적 400,000스텝의 원래 검증 4개 seed는 120초 평균 1,465점·p25 1,437.5점·200초 평균 1,893.75점·생존 171.31초로 좋아졌다. 그러나 추가 검증 8개 seed는 120초 평균 941.875점·p25 757.5점·200초 평균 956.25점·생존 91.39초였다. 기존 모델의 같은 seed 생존 평균 130.78초보다 낮다. 이 차이의 paired bootstrap 95% 구간도 약 -80.26~-9.40초였다.

원래 4개 seed의 순위만 믿고 학습을 늘리지 않기로 했다. 002는 현재 블록을 마친 추가 200,000스텝에서 중단 요청을 남겼다. 이 시점에서 총 연구 예산 사용량은 500,000스텝이 된다. 다음 003은 001의 300,000스텝 모델에서 분기해 조준망·회전 표준편차를 고정하고 몸체·성장·가치 함수를 낮은 학습률 0.00003으로 500,000스텝 적응시킨다. 평가는 다른 개발 seed 43001·44001·45001·46001로 실시한다. 목표는 조준 능력을 보존하면서 이동·생존 정책의 적응을 분리하는 것이다.

수정 뒤 총 예산은 300,000 + 200,000 + 500,000 + 500,000 + 500,000 = 2,000,000스텝이다. 마지막 두 구간의 부모·고정 여부는 개발 평가에 따라 기록하고 정한다. 최초 계획은 `protocol.json`의 initial_plan에 보존하며 최종 20개 독립 seed는 변경하지 않는다.

002 최종 500,000스텝 체크포인트의 추가 검증 8개 seed는 120초 평균 1,228.75점·p25 746.25점·200초 평균 1,446.875점·생존 123.18초였다. 400,000스텝보다 평균은 회복됐지만 기존 모델의 하위 성적·생존을 아직 넘지 못했다. 002의 원래 검증 순위상 best는 400,000스텝이며, 더 넓은 개발 데이터에서 판단할 때 최종 모델과 best 모델을 혼동하지 않는다. 두 모델 모두 후보 기록에 남긴다.

003은 001의 300,000스텝에서 분기한다. 따라서 003 로그의 새 행동 누적 timesteps에는 실패한 002의 200,000스텝이 포함되지 않는다. 전체 연구 비용은 각 experiment.json의 additional_steps를 합산하고, 모델 계보의 학습량과 별도로 보고한다.

## 실행 제한 위반과 수정

추가 개발 평가 sidecar와 새 확률적 재생 평가를 동시에 시작해 학습 6개 + 평가 2개 + 평가 2개 = Python 10개가 잠시 실행되었다. 최대 8개라는 사용자 제한을 위반했다. `process_monitor.jsonl`의 원본 기록과 `process_limit_incident.json`에 남겼다. 확률적 평가를 취소했고 기존 자동 sidecar도 종료했다. 학습은 중단하지 않았다.

이후 보조 Python 작업은 `process_slot.ps1`의 Windows named mutex와 현재 소유 프로세스 수 검사를 함께 사용한다. 보조 작업은 동시에 하나만 실행하고, 6-worker 학습처럼 8개를 사용하는 작업은 보조 작업과 겹치지 않게 같은 잠금을 사용한다. 위반 전후 기록을 지우거나 전체 실행이 제한을 준수했다고 주장하지 않는다.

추가 제한 위반도 있었다. 학습 완료 후 규칙에 따라 실행한 `graphify update .`가 기본값 24 worker로 AST를 추출했다. 설치된 구현을 확인한 결과 ThreadPool이 아니라 ProcessPoolExecutor였다. 당시 모델 평가 Python 2개도 실행 중이었다. 기존 모니터는 학습·평가 프로세스만 추적했으므로 전체 순간 최대 프로세스 수는 측정하지 못했다. 모델 작업 외 도구의 worker 수도 먼저 확인했어야 했다. `graphify_process_limit_incident.json`과 원래 로그를 보존한다.

해당 그래프 작업은 종료됐다. 이후 갱신에는 `GRAPHIFY_MAX_WORKERS=1`을 명시한다. 설치된 구현에서 1은 프로세스 풀을 만들지 않고 순차 추출하는 설정임을 소스로 확인했다. 모델·평가의 관측 최대 10과 그래프 작업의 24-worker 설정을 구분하며, 전체 작업이 8개 제한을 지켰다고 표시하지 않는다.

## 003: 이동 적응과 재생 방식 진단

003의 400,000스텝 체크포인트(이 분기에서 추가 100,000)는 조준망과 회전 log_std가 부모와 비트 단위로 같고 몸체 가중치가 바뀌었음을 직접 검증했다 (`003_frozen_aim_check.json`). 이후 500,000스텝의 넓은 개발 seed 8개는 120초 평균 1,258.75점·p25 892.5점·최종 1,581.25점·생존 132.26초였다. 평균은 개선됐지만 하위 성적은 기존 913.75점보다 조금 낮았다.

학습은 확률적으로 행동하는데 평가·재생은 최빈 행동과 회전 평균만 선택한다는 차이를 확인했다. 같은 003의 400,000스텝 체크포인트를 정책 분포에서 샘플링해 비교했다. 게임 seed마다 Torch 난수를 1,000,003 + game_seed로 고정했다. 최초 실행은 프로세스 제한 위반으로 취소했고, 잠금 적용 후 `_retry` 결과를 완성했다.

동일한 넓은 개발 seed 8개에서 greedy는 120초 평균 805점·p25 638.75점·최종 901.25점·생존 94.91초였고, sampled는 1,140점·1,030점·1,455점·190.08초였다. 기존 모델의 같은 seed는 1,026.875점·913.75점·1,285점·130.78초였다. sampled 방식은 이 개발 표본에서 네 비교 조건을 모두 충족했다. 이는 PPO가 학습한 정책 분포의 재생이며 시범·외부 행동 규칙을 추가한 것이 아니다.

이 결과를 바탕으로 이후 구간은 sampled 평가로 후보를 고르고 재생 방식도 체크포인트와 함께 고정한다. 아직 최종 독립 seed는 열람하지 않았다. 여러 재생 방식을 검토한 개발 데이터 결과를 독립 검증인 것처럼 해석하지 않는다.

이후 003의 600,000스텝에서는 greedy도 넓은 개발 seed에서 120초 평균 1,485점·p25 1,158.75점·최종 1,892.5점·생존 161.88초로 네 조건을 충족했다. 같은 가중치의 sampled는 1,202.5점·1,121.25점·1,605점·172.66초였다. 재생 방식의 우열은 체크포인트에 따라 달라졌다. 따라서 앞서 sampled를 우선하려던 결정을 고정하지 않고 두 모드를 개발 후보로 유지한다.

003을 추가 500,000스텝까지 완료했다. 마지막 800,000스텝의 greedy 모델은 넓은 개발 seed 8개에서 120초 평균 1,927.5점·p25 1,667.5점·200초 평균 2,823.75점·생존 195.6초였다. 해당 8개 seed의 사전 순위가 가장 높고 네 비교 조건을 충족한다. 이 가중치를 004의 부모로 선택하고, 현재 근거가 가장 좋은 greedy를 기본 경과 평가로 사용한다. sampled 후보도 최종 선발 전에 비교한다.

실제 실패 seed 45506의 003 500,000스텝 모델을 캡처했다. 39.4333초·555점·2킬의 GAME OVER 화면이 평가 기록과 일치했다. PNG의 iCCP 경고가 PowerShell 실행기에 의해 실패로 처리되는 문제가 있었지만 이미지·게임 기록은 완성됐다. 실행기를 stderr 메시지 대신 실제 종료 코드로 판정하도록 수정했다. 이 캡처의 최초 실행기 종료 코드는 1이며 이를 성공 코드로 덮어쓰지 않는다.

800,000스텝의 sampled 비교는 120초 평균 1,225.625점·p25 781.25점·최종 1,456.25점·생존 132.28초로 greedy보다 낮았다. 동일 가중치의 비교에서 greedy를 선택할 근거가 명확해졌다. 초기의 불안정한 체크포인트에서 sampled가 좋았다는 결과를 나중 모델에 일반화하지 않는다.

짧은 동일 seed의 sampled 평가를 두 번 반복해 전체 결과가 같음을 확인했고, 평가 전후 Torch RNG도 같았다. 이 검증은 추가 PPO 최적화를 하지 않았다. 기존 소스·모델 40개 해시와 004의 공용 소스 사본도 확인했다 (`checks/replay_and_scope.json`). 잠금 도입 뒤 관측된 최대 Python 수는 8개지만 전체 실행 최대는 앞서 기록한 10개이다.

## 004: 좋은 조준을 보존한 몸체 학습 연장

003의 800,000스텝 모델을 부모로 고정하고 추가 500,000스텝을 학습한다. 학습률 0.00003·score_v7·조준망 고정·greedy 평가를 유지하며 seed는 4104로 갱신했다. 부모 선택 시점·해시는 `phase004_parent_selection.json`에 별도로 고정했다. 기본 4개 평가와 추가 4개 평가를 합쳐 매 100,000스텝마다 같은 넓은 개발 seed 8개를 비교한다.

004 시작 시 보조 평가 스크립트의 param 블록 배치 오류로 최초 실행이 파싱 단계에서 실패했다. Python 평가를 실행하기 전에 고쳤으며 현재 두 PowerShell 스크립트의 구문 검사를 통과했다. 004 시작 시점의 source_code.zip에는 수정 전 보조 스크립트가 들어 있으므로 재현에는 최종 보조 스크립트도 함께 사용한다. 학습기 Python 코드나 정책 수치는 이 수정으로 바뀌지 않았다.

003 800,000스텝 모델을 개발 seed 8개·최대 400초로 연장 평가했다. 평균 점수 3,685점·p25 2,852.5점·평균 생존 278.33초였고 2/8이 400초에 도달했다. 각 120초·200초 점수 집계는 기존 200초 평가와 같았다. 이 데이터도 개발 평가이며 최종 독립 검증이 아니다.

004는 추가 500,000스텝을 완료했다. 연장한 체크포인트들이 부모의 개발 순위를 넘지 못해 005 초기화에는 다시 003의 800,000스텝 모델을 선택했다. 원래 부모와 새 seed로 더 학습하는 것이 늘 성능을 높이지는 않았다. 모든 구간의 체크포인트와 평가를 보존한다.

004의 Python 학습기는 completed·additional_steps=500000·final.zip을 정상 기록했으나 Windows Start-Process의 ExitCode가 null로 반환돼 외부 실행기가 코드 1로 종료했다. `004_completion_recovery.json`에 실제 Python 종료 코드는 확인 불가, 실행기 종료 코드는 1임을 보존했다. 프로세스 핸들을 시작 직후 확보하도록 수정한 뒤 정상 종료 0과 의도적 실패 3을 실제 작은 프로세스로 검증했다 (`checks/native_process_exit.json`). 학습을 다시 돌리거나 스텝을 중복 계산하지 않았다.

## 005: 몸체를 보존한 조준 정밀화

총 연구 1,500,000스텝 이후 마지막 500,000스텝을 시작했다. 개발 seed 8개의 네 조건을 충족하는 후보 중 120초 평균+p25·최종 평균·생존 순으로 부모를 골랐다. 선택 결과와 후보 전체는 `phase005_parent_selection.json`에 시작 전에 보존했다.

부모는 003의 800,000스텝 모델이다. 이동·성장·CNN 가중치를 고정하고 회전·발사·가치 함수만 full 게임에서 학습한다. learning_rate=0.00002, entropy=0.001, reward=score_v7, seed=8105이다. 목표는 이동 안정성을 유지한 채 실제 적·성장 상태에서 연속 회전과 발사 타이밍을 정밀화하는 것이다. 이 구간이 끝나면 연구 학습 합계가 정확히 2,000,000스텝이 된다.

005의 첫 추가 100,000스텝을 부모와 비교해 CNN·이동·성장·몸체 actor의 모든 가중치가 비트 단위로 같고 조준망만 바뀌었음을 확인했다 (`005_frozen_body_check.json`). 그러나 개발 seed 8개의 120초 평균 1,648.125점·p25 1,145점·최종 2,214.375점·생존 161.84초로 부모보다 낮았다. 가중치 일부의 보존은 닫힌 루프의 전체 게임 결과를 보존한다는 뜻이 아니다. 좋은 조준·이동 조합의 부모를 유지하고 나머지 구간도 실제 점수로 평가한다.

## 초기 2,000,000스텝 결과의 진화 오류 발견

처음 5개 구간 합계 2,000,000스텝을 완료하고 005의 1,200,000스텝 계보 모델을 선택했다. 최초 독립 평가 20개 seed에서는 평균 최종 3,402.5점·생존 301.85초였으나, 이후 실제 화면에서 기체가 계속 rookie인 점을 추적해 중요한 디코더 오류를 발견했다. 이 수치를 수정된 구현의 성능으로 확정하지 않는다.

디코더의 `choices.astype(int)`를 풀어 받은 값은 Python int가 아니라 numpy.int64였다. PlayerControl의 진화 인덱스가 그대로 전달돼 `PlayerProgression.choose_reward()`의 isinstance(index, int) 검사에서 무시됐다. 기존 테스트는 값이 같은지만 확인하고 실제 게임 진화를 검증하지 못했다. player 진화는 적 진화에도 영향을 주므로 원래 의도한 동작과 게임 전이가 달랐다.

범주를 이미 정수 값으로 검증한 뒤 `map(int, choices)`로 변환하도록 새 디코더 한 곳을 고쳤다. 공용 코어는 변경하지 않았다. 테스트는 반환 타입이 Python int인지와 10레벨 보상 상태에서 실제 TankEnv.step 후 기체가 twin으로 바뀌는지 확인하도록 보강했다 (`checks/evolution_application.json`). 점수로 10레벨을 만든 설정은 검증 fixture이며 PPO 학습 데이터가 아니다.

처음의 선택·모델·독립 평가·그림은 `initial_decoder_results/`에 복사 보존했고 현재 모델 카드는 재평가 필요 상태로 바꿨다. 가중치는 같은 SHA256 205b19d907f233f4a89f6770008ce1a30d32f23d2921be3f380286b0163a8bea를 유지한다. 먼저 수정된 코드에서 같은 개발 seed 8개를 평가한다. 수정 후 최종 독립 검증은 기존에 보지 않은 61001~62910의 20개 seed를 사용하며 시작 전에 `decoder_correction_protocol.json`에 고정했다. 최초 51001~52910 결과를 수정된 구현의 독립 성능으로 재사용하지 않는다.

수정된 개발 seed 8개 결과는 120초 평균 2,187.5점·p25 1,832.5점·최종 3,037.5점·생존 179.88초였다. twin·sniper·flank로 실제 진화한 에피소드가 기록됐다. 기존 모델에 대한 네 개발 조건을 모두 충족해 추가 연구 학습 없이 같은 가중치·greedy 방식을 유지하기로 결정했다. `corrected_candidate_selection.json`에 새 독립 평가 전에 고정했다. 처음 2,000,000스텝에서 진화 요청은 제대로 학습·적용되지 않았다는 사실을 최종 모델의 한계로 함께 남긴다.

수정 후 20개 seed의 기준 모델과 후보를 ProcessPoolExecutor(max_workers=2)로 검증한다. 모델별 추가 worker를 중첩하지 않고 각 worker의 Torch 스레드를 1로 둔다. coordinator·launcher·resource tracker를 포함한 관측 프로세스 수는 5개였다. 기존 실험 2,000,000스텝과 기능 검증용 PPO 스텝은 분리해 집계한다.

## 수정 후 최종 평가 완료

사전 고정한 새 seed 20개에서 수정된 후보의 120초 평균 점수는 1,530점(기존 1,049.25), 하위 25% 경계 912.5점(기존 778.75), 최종 평균 2,902점(기존 1,508), 평균 생존 262.84초(기존 222.67)다. 최종 점수는 같은 시드에서 14승 6패이며 평균 차이의 paired bootstrap 95% 구간은 +594~+2,282점이다. 평균 생존 차이 구간은 -32.18~+111.79초로 0을 포함한다. 400초 생존은 5/20 대 2/20이다. 네 승격 조건을 통과했지만 매 시드나 장기 생존 개선을 보장하지 않는다. 전체 결과는 RESULTS.md와 corrected_heldout_comparison.json에 정리했다.

selected_model.zip의 SHA256은 처음 고정한 205b19d907f233f4a89f6770008ce1a30d32f23d2921be3f380286b0163a8bea 그대로다. 최종 독립 평가 후 후보를 교체하거나 추가 연구 PPO 학습을 하지 않았다. 공용 기본 모델도 교체하지 않았다. 검증용 PPO는 수정 전 64와 수정 후 64스텝으로 합계 128이며 최종 모델과 별개다.

수정 후 실제 게임 화면도 seed 505와 61001에서 캡처했다. 505는 twin으로 진화하고 218.7833초에 4,110점·15처치로 종료했다. 61001은 flank로 진화하고 252.8833초에 2,855점·9처치로 종료해 최종 평가 원자료와 정확히 일치했다. 두 에피소드 모두 사망 사례이며 성공 장면만 선별한 영상이 아니다. 디코더 bounds·결합 log probability·tanh 보정·실제 PPO 업데이트·저장/로드·실제 회전·실제 진화 검증도 통과했다.

최종 검증은 보호 파일 40개, 모델·디코더 해시, 분기 학습 합계, 동결된 몸체·CNN 가중치, TensorBoard 원자료를 확인하고 final_source_code.zip에 최종 소스와 재사용 소스를 보존한다. checks/final_validation.json에 검증 결과를 남긴다. graphify는 GRAPHIFY_MAX_WORKERS=1로 순차 갱신하고 모니터를 종료한다. 앞서 발생한 프로세스 제한 위반 두 건과 초기 진화 버그는 완료 기록에서 숨기지 않는다.
