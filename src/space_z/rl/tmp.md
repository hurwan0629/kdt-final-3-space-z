# RL 코드 작성과 변경 판단 기준 — AGENTS.md 초안

기존 [AGENTS.md](AGENTS.md)의 작업 범위 규칙을 보완하는 검토용 문서다.
현재 파일은 자동 적용되는 AGENTS.md가 아니다.

## 목적

코드의 역할, 데이터의 의미, 실행 흐름을 이해하고 변경하는 데 필요한 문맥을 줄인다.
줄 수나 특정 표현 형식보다 책임의 명확성, 변경의 국소성, 기존 동작의 보존을 기준으로 판단한다.
아래 작성 방식은 기본 권장 사항이며, 구체적인 선택은 해당 코드의 복잡도와 사용 맥락에 맞춘다.

## 요청과 작업 범위

- 사용자가 원하는 결과와 현재 요청의 수준을 구분한다. 검토·설계·초안 제시는 실제 파일 변경과 별개의 작업이다.
- 후속 요청은 앞서 합의한 목적·범위·진행 방식을 이어서 해석한다. 제안과 합의, 구현 완료 상태를 구분한다.
- 구현은 허용된 파일과 기능 범위에서 진행한다. 개인 폴더와 범위 밖 파일의 변경에는 별도 요청이 필요하다.
- 단계별 확인이 요청된 작업은 합의한 단계까지 수행하고 결과를 제시한다. 실행과 검증도 사용자가 정한 범위를 따른다.
- 구조나 인터페이스에 큰 영향을 주는 선택은 구현 전에 영향과 대안을 설명한다. 합의한 범위 안의 세부 구현은 자율적으로 진행한다.

## 이름과 책임

- 이름만으로 대상과 역할을 예상할 수 있게 한다. 수량의 단위나 데이터의 시점이 의미를 바꾸는 경우 이름에 반영한다.
- 관례, 주변 코드와의 일관성, 프로젝트 문맥, 읽는 사람의 이해를 함께 고려한다. 이름의 길이보다 의미를 정확하게 전달하는지가 중요하다.
- 이름이 실제 책임의 범위를 표현하는지 확인한다. 지나치게 넓은 이름과 일부 기능만 드러내는 이름 모두 독자의 예측을 어렵게 할 수 있다.
- 인접한 개념은 서로 구분되는 이름을 사용한다. 클래스·함수·변수·키 사이의 용어를 일관되게 연결한다.

## 데이터 구조와 객체 구성

- 설정과 기록의 필드, 중첩 관계, 선택 항목을 코드에서 파악할 수 있게 한다. 데이터클래스·TypedDict·dict 등은 데이터의 용도와 전달 경계에 맞게 선택한다.
- 기존 설정과 도메인 객체를 먼저 검토하고 재사용한다. 같은 사실의 정의와 기본값은 한곳에서 관리한다.
- 객체 생성이나 데이터 변환이 겹쳐 흐름을 읽기 어려우면 의미 있는 중간 결과로 풀어 쓴다. 직접 표현이 충분히 명확한 부분은 그대로 유지한다.
- 인자 전달은 중요한 선택이 보이면서도 같은 설정을 반복 나열하지 않도록 구성한다. 응집된 설정 묶음과 개별 인자의 명시성을 상황에 맞게 선택한다.
- 데이터의 생성·변환·전달·저장 경계를 추적할 수 있게 한다. 내부 표현과 외부 형식의 변환은 해당 경계에서 책임진다.
- 타입 정보는 구조 이해를 돕고, 외부 입력 검증은 실행 시 유효성을 보장한다. 두 역할을 함께 고려한다.

## 설명과 읽기 흐름

- 코드와 이름을 먼저 명확하게 하고, 주석과 docstring으로 이해에 필요한 배경·의도·제약을 보완한다.
- 설명의 길이와 상세도는 내용의 복잡도와 독자에게 필요한 정보에 맞춘다. 단순한 역할에는 짧은 설명을, 복잡한 계약에는 충분한 설명을 제공한다.
- 여러 처리 단계가 이어지는 곳은 배치·중간 이름·구간 주석을 활용해 단계와 연결 관계를 드러낸다.
- 데이터클래스 등 주요 구조의 설명은 용도와 책임을 이해할 수 있게 작성한다. 필드별 설명은 이름과 타입만으로 부족한 의미를 중심으로 보완한다.

## 모듈 경계와 변경

- 파일의 길이보다 책임, 함께 변경되는 규칙, 의존 방향을 기준으로 모듈 경계를 정한다.
- 진입점에서 전체 실행 순서를 파악할 수 있게 하고, 세부 구현은 응집된 책임 안에 둔다.
- 관련 데이터 구조와 처리를 가까이 배치한다. 분리로 얻는 이해의 이점과 파일 간 이동 비용을 함께 판단한다.
- 추상화는 복잡성을 숨기거나 변경 영향을 줄이는 등 구체적인 이점이 있을 때 도입한다.
- 동작을 유지하는 구조 변경과 기능 변경은 각각의 영향을 확인할 수 있도록 구분해 진행한다.

## 호환성과 영향 범위

- 변경 전에 생성부·소비부·외부 인터페이스를 확인하고, 이름이나 구조 변경을 관련 참조 전체에 일관되게 반영한다.
- 내부 표현의 개선과 외부 계약의 변경을 구분한다. 기존 설정·로그·실행 이력·체크포인트·재개 동작은 호환성을 보존한다. 계약 변경이 필요하면 영향과 이전 방식을 별도로 합의한다.
- 재개 설정에서는 생략한 값과 명시한 값을 구분하고, 사용자가 지정한 항목만 덮어써 부모 모델의 설정을 보존한다.
- 파일 이동 시 import뿐 아니라 실행 명령, 상대 경로, 병렬 처리, 저장된 객체의 복원 경로도 고려한다.
- 상태 소유권, 객체 공유, 이벤트 소비, 처리 순서와 난수 사용처럼 동작에 영향을 주는 관계를 함께 확인한다.

## 검증과 보고

- 변경의 영향에 맞는 검증을 선택한다. 저장 형식이나 재개 동작이 바뀔 가능성이 있으면 기존 결과와 비교한다.
- 검증도 허용된 작업 범위 안에서 수행한다. 추가 파일이나 의존성 변경이 필요하면 현재 요청에 포함되는지 먼저 판단한다.
- 확인한 사실, 추정, 미확인 영역을 구분한다. 저장소 검색이나 대체 객체 검증의 결과를 외부 실행 환경이나 실제 학습 전체에 확대해 단정하지 않는다.
- 완료 보고에는 결과와 검증 범위, 남은 제약을 전달한다.
