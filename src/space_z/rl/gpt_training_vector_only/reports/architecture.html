01

위에서 아래로 읽습니다. B는 배치 크기, N은 슬롯 수, D=64는 각 특징의 폭입니다. 파란 흐름은 새로 제안하는 학습 경로이며, 5139차원 입력과 5개 행동 형식은 기존 것을 사용합니다.

02

첫 벡터에는 무엇이 들어 있나

현재 관찰 명세 Python 슬라이스는 끝 인덱스를 포함하지 않습니다. 아래 최대 개체 수는 실제 존재 수가 아니라 관찰 슬롯 수입니다. 부족한 슬롯은 전부 0이고, 벽에 가린 개체도 관찰 범위 안이면 포함됩니다.

실제 차원 비율입니다. 지형이 약 76.2%를 차지합니다. 자기 상태·성장은 위 막대에서 함께 표시합니다.

자기 상태

거리순 슬롯 ≠ 개체 ID
종류별로 가까운 개체부터 채웁니다. 다음 프레임의 같은 슬롯이 같은 개체라는 보장은 없습니다. 새 모델에는 슬롯 순번 임베딩을 추가하지 않습니다.
위치는 이미 상대 좌표입니다
dx는 관찰 반폭, dy는 관찰 반높이로 각각 정규화합니다. 오른쪽·아래쪽이 양수입니다. 포신 기준 각도나 추천 회전값은 새 입력에 추가하지 않습니다.
One-hot은 어떤 순서인가?

자신의 기체, 적군의 기체, 전직 후보 기체는 모두 현재 SHIPS의 동일한 21개 순서를 사용합니다. 특정 기체 위치만 1이며 나머지는 0입니다.

천체 종류는 [square, triangle, pentagon]입니다. 탄환 두 항목은 [plasma 여부, shell 여부]이며 다른 종류는 둘 다 0일 수 있습니다.

03

종류별 인코더의 모든 레이어

제안 개체별 MLP는 마지막 축에 적용합니다. 같은 종류의 개체끼리는 가중치를 공유하고, 적군·천체·탄환은 서로 다른 인코더를 사용합니다. 출력의 64개 숫자는 학습된 특징이며 사람이 정한 64개 항목이 아닙니다.

플레이어 인코더

자기 상태 10개와 성장 상태 123개를 모두 사용합니다.

obs[:, 0:133] · [B, 133]
Linear(133, 64)[B, 64]
GELU[B, 64]
Linear(64, 64)[B, 64]
LayerNorm(64)[B, 64]
Unsqueeze(1)[B, 1, 64]

이 출력이 attention의 질의와 첫 잔차 연결에 사용됩니다.

적군 인코더

적군 하나의 31개 정보를 먼저 해석합니다.

obs[:, 133:412] → [B, 9, 31]
Linear(31, 64)[B, 9, 64]
GELU[B, 9, 64]
Linear(64, 64)[B, 9, 64]
LayerNorm(64)[B, 9, 64]
+ 적군 타입 임베딩[B, 9, 64]

첫 원본 항목인 존재 여부로 유효 슬롯을 표시합니다. 9개를 이 단계에서 합치지 않습니다.

천체 인코더

종류·체력·위치 등 천체 하나의 10개 정보를 사용합니다.

obs[:, 412:712] → [B, 30, 10]
Linear(10, 64)[B, 30, 64]
GELU[B, 30, 64]
Linear(64, 64)[B, 30, 64]
LayerNorm(64)[B, 30, 64]
+ 천체 타입 임베딩[B, 30, 64]

30개 특징을 개별로 유지합니다. 목표물 하나를 고르는 argmin은 없습니다.

탄환 인코더

상대 위치와 속도를 보고 위협의 활용 방식을 학습합니다.

obs[:, 712:1224] → [B, 64, 8]
Linear(8, 64)[B, 64, 64]
GELU[B, 64, 64]
Linear(64, 64)[B, 64, 64]
LayerNorm(64)[B, 64, 64]
+ 탄환 타입 임베딩[B, 64, 64]

회피 방향이나 충돌 예상 시간을 별도 계산해 넣지 않습니다.

지형 인코더 · 위치별 특징을 남기는 CNN

기존 CNN 앞부분과 같은 합성곱 규격을 제안합니다. 새 가중치로 학습하며, 전체 지형을 하나로 평균내는 단계는 두지 않습니다.

obs[:, 1224:5139] → [B, 3, 29, 45]
Conv2d(3, 8, k=5, s=3, p=2)[B, 8, 10, 15]
ReLU[B, 8, 10, 15]
Conv2d(8, 16, k=3, s=2, p=1)[B, 16, 5, 8]
ReLU[B, 16, 5, 8]
Permute → 공간 축 Flatten[B, 40, 16]
Linear(16, 64)[B, 40, 64]
+ Linear(2, 64)(행·열 좌표)[B, 40, 64]
+ 지형 타입 임베딩[B, 40, 64]
위치 정보의 의미
5 × 8 출력 위치의 행·열을 각각 [-1, 1]로 정규화해 학습 가능한 Linear(2, 64)로 투영합니다. 이것은 CNN 출력 위치를 구별하는 정보입니다. 개체의 좌표와 정확히 일치하는 별도 충돌 판정이나 시야선 계산은 아닙니다. 각 CNN 위치는 원본 주변 영역을 겹쳐서 봅니다.

특징 연결 · 수를 줄이는 단계가 아닙니다

적군      [B,  9, 64] ┐
천체      [B, 30, 64] ├─ torch.cat(..., dim=1) → [B, 143, 64]
적 탄환   [B, 64, 64] │
지형      [B, 40, 64] ┘

타입 임베딩은 4 × 64개의 학습 파라미터입니다. 각 종류가 무엇인지 알려주며 개체의 우선순위를 고정하지 않습니다. 빈 개체는 임베딩·편향 때문에 0이 아닐 수 있으므로 반드시 attention 마스크로 제외합니다. 지형 40개 위치는 모두 유효합니다.

04

Cross-attention 내부를 펼치면

제안 플레이어 질의 하나가 개체·지형 143개를 참고합니다. 시간 순서를 다루는 causal mask는 없고, 존재하지 않는 개체를 제외하는 padding mask만 있습니다. 이 첫 설계에는 개체끼리의 self-attention이 없습니다.

블록 1개 · 특징 폭 64 · head 4개 · dropout 0
순서레이어 / 계산출력 형태
1플레이어 특징에 LayerNorm(64) → Query 입력[B, 1, 64]
2143개 특징에 별도 LayerNorm(64) → Key / Value 입력[B, 143, 64]
3학습 가능한 Q·K·V 투영 각각 Linear(64, 64)Q: [B, 1, 64]
K, V: [B, 143, 64]
44개 head로 분리 · 각 head 폭 16Q: [B, 4, 1, 16]
K, V: [B, 4, 143, 16]
5QKᵀ / √16 → 빈 개체 위치에 −∞ → Softmax[B, 4, 1, 143]
6가중치 × V → head 연결 → Linear(64, 64)[B, 1, 64]
7플레이어의 원래 특징을 더하는 잔차 연결z = player + attention_output
8LayerNorm(64) → Linear(64, 128) → GELU → Linear(128, 64)[B, 1, 64]
9z를 더하는 잔차 연결 → 질의 축 제거[B, 64]
여러 개체를 참고할 수 있습니다
각 head는 서로 다른 가중치를 학습할 수 있습니다. 하나는 가까운 벽, 하나는 적을 보도록 역할을 미리 지정하지는 않습니다. attention이 여러 정보를 함께 참고하는 방식은 보상으로 학습합니다.
정보 손실이 완전히 없어지는 것은 아닙니다
개체별 정보를 attention 전까지 유지하지만 마지막에는 64차원으로 요약합니다. 정밀 조준과 개체 간 복잡한 관계를 충분히 표현하는지는 아직 검증하지 않았습니다.
05

22개 출력이 5개 행동이 되는 과정

행동 형식과 디코더는 기존 연속 회전 실험의 계약을 유지합니다. 새 정책에서는 별도의 목표물 입력망 없이 통합 특징 하나에서 행동 파라미터를 만듭니다.

Actor

통합 특징 [B, 64]
Linear(64, 128)[B, 128]
GELU[B, 128]
Linear(128, 22)[B, 22]

출력 22개를 9 + 1 + 1 + 6 + 5로 나눕니다. 회전 표준편차용 학습 파라미터 log_std 1개는 별도로 둡니다. 기존처럼 관찰과 독립적인 값이며 초기값 제안은 −1.2입니다.

Critic

통합 특징 [B, 64]
Linear(64, 128)[B, 128]
GELU[B, 128]
Linear(128, 1)[B, 1]

Actor와 다른 가중치를 사용합니다. 인코더·attention은 공유합니다. 상태 가치로 PPO 학습을 돕고 최종 action에는 들어가지 않습니다.

학습 중에는 분포에서 샘플링합니다. deterministic 실행은 이동·성장 최빈 선택, tanh(회전 평균), 발사 logit > 0을 사용합니다. 투자·전직 불가 선택지만 기존 관찰의 가능 여부로 마스크하며 0번은 항상 허용합니다. 발사 요청과 실제 탄환 생성은 재장전·쿨다운 등의 게임 상태에 따라 다릅니다.

06

무엇을 정했고, 무엇을 확인해야 하나

01

데이터 형식은 명시적으로

관찰 구간 분리, reshape, 이미 적용된 정규화, 종류별 타입과 공간 좌표를 사용합니다. 원본 관찰 생성기의 거리순 정렬·관찰 범위·슬롯 상한은 그대로 남습니다.

02

대상 선택은 학습으로

가시성 검사로 후보를 지우거나 적군 거리에 0.8을 곱하지 않습니다. 상대 각도·예상 조준점·회피 방향을 계산해서 추가하지 않습니다.

03

작은 구조에서 비교 시작

첫 제안은 4 heads, 폭 64, cross-attention 블록 1개입니다. 006은 조준망 추가 전 비교 기준이며, 이 새 정책은 가중치를 처음부터 학습할 계획입니다.

설명력을 검증하는 방법

Attention 가중치는 참고한 정보의 단서입니다. 실제 행동 원인의 증명으로 취급하지 않습니다. 아래 검사는 입력을 바꾸고 행동 분포가 어떻게 달라지는지 함께 봅니다.

개체 순서 변경정보와 마스크를 함께 재배열했을 때 정책 출력이 같아야 합니다.
빈 슬롯 제외마스크된 빈 슬롯의 값이 바뀌어도 출력에 영향을 주지 않아야 합니다.
지형 정보 개입정해 둔 장면에서 벽 입력을 변경하고 이동·회전·발사 분포의 변화를 관찰합니다.
개체 정보 개입특정 개체를 가린 전후의 행동 분포와 attention을 함께 비교합니다.
이번 파일의 범위
이 문서는 학습 전에 작성한 구조 설계입니다. 실제 구현·연결 검사·학습 상태는 갤러리의 실험별 기록에 표시합니다. 보상 계수, 학습 커리큘럼, PPO 하이퍼파라미터는 이 문서에서 확정하지 않습니다. 기본 관찰 형식의 합계와 레이어 차원은 검산하되 실제 정책 구현·체크포인트 이전·학습·성능 검증은 아직 수행하지 않습니다.
