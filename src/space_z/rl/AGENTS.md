# RL 작업 규칙

이 폴더와 하위 폴더에서 학습 코드를 작성하거나 수정하는 에이전트에게 적용합니다. 사용자의 직접적인 지시를 우선하며, 사용법은 [README.md](README.md)를 참고합니다.

## 기본 수정 범위

- 사용자가 지정한 학습 파일만 작성·수정합니다. 예: `train.py` 수정 요청은 해당 파일만 수정합니다.
- 문서·테스트·의존성 설정·다른 학습 파일을 부수 작업으로 자동 변경하지 않습니다. 해당 파일의 변경도 직접 요청받은 경우에만 수행합니다.
- 기존 사용자 변경을 보존합니다. 현재 파일을 확인하고 필요한 부분만 수정합니다.

## 작업 환경 코드는 직접 요청이 있을 때만 수정

다음은 학습 코드가 사용하는 기존 환경입니다.

- `environment.py`, `actions/`, `observations/`, `rewards.py`
- `evaluate.py`, `resource_monitor.py`, 공개 import를 정하는 `__init__.py`
- `rl/` 밖의 게임 코어·렌더링·설정 코드, 맵·에셋 및 프로젝트 의존성 설정

**사용자가 환경 변경을 직접 요청하지 않았다면 위 코드를 수정하지 않습니다. 수정할지 묻거나, 수정 허가를 요청하거나, 환경 변경을 권유하지도 않습니다.**

"PPO 학습 코드 작성", "학습 오류 해결", "학습 속도 개선" 등의 요청만으로 환경 변경이 허용되었다고 해석하지 않습니다. 작업 중 발견한 문제를 이유로 수정 범위를 확대하지 않습니다.

## 기존 인터페이스로 해결

- `TankEnv`에 관찰 생성기·행동 해석기·보상 계산기를 전달합니다. 학습 코드에서 게임 코어를 직접 진행하거나 전투 이벤트를 별도로 소비하지 않습니다.
- `GameConfig`, `ObsConfig`, `RewardConfig`, `EnvConfig`의 인스턴스를 학습 코드에서 생성해 전달하는 것은 허용합니다. 원본 설정 파일이나 기본값은 변경하지 않습니다.
- 관찰·행동·보상 형식은 기존 인터페이스를 사용합니다. 학습 라이브러리에 필요한 연결은 요청받은 학습 파일 안에서 처리합니다.
- 의존성이 필요하면 설치 명령을 안내합니다. 의존성 파일은 직접 요청 없이 수정하지 않습니다.
- 검증은 기존 테스트 또는 짧은 실행으로 수행합니다. 검증을 이유로 다른 소스·테스트 파일을 추가하거나 수정하지 않습니다.

## 현재 범위에서 해결할 수 없는 경우

허용된 학습 파일에서 해결 가능한 부분까지만 작업합니다. 환경 변경이 반드시 필요하면 막힌 사실과 원인을 짧게 보고하고 멈춥니다. **환경 코드를 바꿀지 질문하지 않습니다.** 사용자가 이후 직접 변경을 요청한 경우에만 해당 작업을 진행합니다.
